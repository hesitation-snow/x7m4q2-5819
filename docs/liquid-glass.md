# Liquid glass bottom bar: implementation and verification boundaries

## Rendering paths

- Flutter 3.47.0 / Dart 3.13.0 in this workspace provides `ImageFilter.shader` and `ImageFilter.isShaderFilterSupported`.
- On a supporting Impeller backend, `shaders/liquid_glass.frag` samples the **engine-provided GPU backdrop texture** and uses a rounded-rectangle signed-distance field to estimate edge normals and attenuate inward sampling to a narrow edge band; the lens core samples the original source unchanged. The selected destination's icon and label are prepainted at low alpha, clipped to the lens, and placed before the root `BackdropFilter`, so their glyph pixels participate in the filter input; the normal foreground row remains the sole semantic/hit-test layer. A subpixel RGB split (max 0.72 physical px) is confined to the same refraction edge and increases slightly with press/deformation; it is zero when refraction is zero. There is no `toImage`, CPU readback, per-frame screenshot, or unrelated package dependency. Flutter may internally retain a full render-pass input texture. The filter is two-stage: `ImageFilter.compose(outer: ImageFilter.blur(sigmaX: 22, sigmaY: 22), inner: ImageFilter.shader(shader))`. The shader reads the root backdrop before a native Gaussian blur softens the bar. This is image filtering, not a dark overlay or sparse taps.
- Skia, unsupported engines, and shader-loading failures use ordinary `ImageFilter.blur`. This is **not refraction**. Settings describe the current engine capability rather than claiming a shader loaded or a device passed visual verification.
- The formal Android release manifest sets `EnableImpeller=true`; the separately named Skia/stable variant is retired. Unsupported engines and shader-loading failures retain the runtime blur fallback.
- Although embedding metadata accepts `ImpellerBackend`, this SDK's `flutter_main.cc` handles explicit GLES/Vulkan selection only outside `FLUTTER_RELEASE`. The formal release therefore uses automatic Impeller backend selection.

## Coordinate contract

`u_size` is the input **render-pass texture size**, not the 292x50 widget size. During paint the custom render object transforms the current lens center/bounds through `getTransformTo(null)` and device pixel ratio. The shader subtracts this physical-pixel center before dividing by the physical lens half-size, and only normalizes source samples by `u_size` at texture lookup. This includes current width and current slide-away translation without a one-frame post-layout measurement delay. GLES sampling reverses texture Y as required by the SDK.

This is a **root-Scaffold-pass implementation**, not a generic arbitrarily nested backdrop effect. The component does not place an Opacity/saveLayer around its backdrop. Its own foreground opacity is a sibling layer. Known ancestor opacity/animated-opacity below 1, ShaderMask, or BackdropFilter uses blur instead. A mismatched input texture/view size bypasses displacement and returns the original input; the outer Gaussian still blurs it. The public Flutter API does not expose every render-pass origin: arbitrary custom saveLayers with equal-sized shifted inputs are not universally detected. Route transitions, nested effects, display scaling/DPR, and mid-collapse rendering still require GPU visual verification. No claim of exact iOS reproduction is made.

## Unified frost and contrast

The “液态玻璃底栏” option is a direct persisted switch in Settings → 显示; its detailed preview and controls remain available in the lab. The switch retains `liquid_glass_bottom_bar_enabled` compatibility, and legacy `liquid_glass_intensity` remains ignored. Seven continuous sliders share one immutable `GlassConfiguration` ValueNotifier with Home: background blur 0–40 (3), neutral tint 0–100% (9%), refraction 0–0.25 (0.25), highlight 0–100% (74%), width 220–360 dp (252), height 40–72 dp (59), and bottom floating gap 0–48 dp (18). A separate “滚动时保持底栏显示” switch defaults off. Reset restores all glass and layout parameters without changing the enabled state. Refraction zero disables displacement even during press; the Skia slider is disabled with explanation. Runtime support is capability detection, not a claim of device validation or successful shader loading.

The pinned preview uses the actual `LiquidGlassBottomBar` and independently scrollable text/color blocks, not screenshots. It reflects custom width, height, and bottom gap live, remains visible while controls scroll, always previews glass even if Home is disabled, and labels that distinction. No saveLayer/opacity wraps the preview backdrop. Native Gaussian remains outside the inner shader; both rendering paths share blur/tint/highlight parameters and adapt icon/label/lens sizing to the configured bar height. Light `#f5f5f7`, dark `#202026`, and existing foreground contrast remain unchanged.

Validated finite numeric preferences clamp to range; wrong types/NaN/infinity use defaults. Slider and switch changes notify immediately; a 300 ms debounce and onChangeEnd save all layout/glass values through the serialized preferences queue, with dispose flushing pending changes and asynchronous errors logged. No per-frame disk writes or image readbacks.

The lab index also has persisted “每日开宝箱” and “加载全部勋章” feature toggles. Daily treasure defaults off; the task center listens live and only inserts its dedicated card when enabled and data is available. Full-medal loading defaults to the `YOMIRU_ALL_MEDALS` build value (off in normal builds); enabling it requests 50 entries per page and follows all server pagination, including test or unavailable entries. The medal shop reloads when this setting changes.

Current SDK source confirms compose wraps the original input with the inner filter before the outer filter (`engine/src/flutter/impeller/display_list/image_filter.cc:94–110`). `runtime_effect_filter_contents.cc:46–47` obtains that original input snapshot; its source coverage method at 183–186 returns the requested output limit. Keeping blur outside avoids feeding a blur-expanded/rebased snapshot to the root-coordinate shader. Public API saveLayer limitations below still apply.

## Interaction and accessibility

Default visible surface is 252x59; width is adjustable from 220–360 dp and height from 40–72 dp, with the rendered width constrained by available screen space. Height proportionally scales icon, label, and lens geometry. Floating gap is configurable from 0–48 dp but never intrudes into the device safe area. “滚动时保持底栏显示” makes the liquid-glass bar ignore the feed-collapse fraction while the header continues its existing scroll behavior. The book-detail reading action plays its slide/fade entrance once when the book first loads; later scroll hide/show toggles are immediate. Its Scaffold FAB animator is set to `FloatingActionButtonAnimator.noAnimation` because the visibility/entrance wrappers conceal the extended-FAB type from Scaffold's default entrance detector, which otherwise applies a `RotationTransition` turn. The publisher card keeps the avatar, publisher name on the first line, and follow action; the second line shows only a schedule icon and the book's last-updated timestamp, with no UID or medals. A 12 dp gap separates the card from the book metadata without a divider line. Selection position is normalized by actual width. One persistent animation-controller listener handles repeated taps and external updates. Drag cancel returns to the parent's selected item; rejected selection requests reconcile. External selection interrupts an active drag. Press increases lens height/width; drag adds constrained stretch, and release uses VelocityTracker plus independent X/Y SpringSimulation controllers to settle deformation. This spring animates deformation size, not position velocity. Highlight glint strength follows press and spring deformation. Reduced motion and external selection stop spring activity and clear deformation.

## KernelSU comparison limits

The SDF edge refraction is a practical approximation, not a pixel-match claim. The selected icon/label is now low-alpha prepainted into the same root-pass backdrop, clipped to the moving capsule, and sampled along with the page under the refracting edge; the regular foreground row is still drawn on top and remains the only interactive/accessibility row. The ghost layer is gated off on blur fallback. Dynamic edge glint and bounded subpixel RGB dispersion are implemented. Their actual visual appearance, layer composition, and performance still require Impeller-device validation.

The app animation switch is subscribed directly, and system reduce-motion is observed. Both stop an active transition and snap to the current selection. Each destination has one labelled, selected, tappable semantics button, keyboard Enter/Space activation, visible keyboard focus, and bounded large text. Keyboard insets and fully hidden bars remove hit targets. The bottom Align has heightFactor=1, avoiding an expanded Scaffold navigation slot. Feed list/grid and profile lists add bottom inset to scroll content, not padding around the whole page, keeping the background visible through the bar.

## Verification scope

Widget tests exercise the ordinary-blur host path, Scaffold sizing/page hit tests, narrow-width navigation, rapid taps/external updates, press/stretch/cancel, parent-rejected selection, release spring/reduce-motion, sampling-ghost ordering/inert semantics, custom preview dimensions/floating gap, and the keep-visible scroll override. Preference tests cover bounds, debounce, persistence, reload, and live updates. CPU reference tests cover capsule SDF distance, edge attenuation, bounded motion-driven highlight, and edge-only subpixel dispersion. Android release compilation checks packaged shader assets. These checks do **not** establish real-device Impeller rendering correctness or frame-time performance. Neither APK is installed automatically; Android and iOS GPU visual/performance acceptance remains pending.
