# 本轮优化的实机验收

本轮不增加功能，不改变阅读器正文排版和进度换算算法。主要修复阅读时长重复上报、每日任务跨天状态、封面揭开状态串到其它作品、过滤后无法继续分页，并收敛用户主页的权限查询和插画预加载；设置页独立为一个文件。

- Release APK 构建、R8 压缩、签名校验通过，文件大小 69,990,868 字节（约 66.7 MiB），支持 ARM64、ARMv7、x86_64。
- APK：`build/qa-20260905/Yomiru-1.3.0-optimization-test.apk`。
- APK SHA-256：`57c311ab5f6178451c03288bf339dd6e907e67911337301b094973dc9459b951`。
- 使用现有 `CN=Yomiru Release` 证书。未改版本号、未安装到设备、未提交或推送，README 保持不变。
- 本轮共 181 项测试，按最终全量运行成功的 177 项加动态布局单独重跑的 4 项，已分批通过。另对任务中心、阅读上报、缓存清理和资料页相关测试单独重跑，27 项通过。

## 测试前

- 测试包使用 Release 编译、项目现有签名和 R8 配置，版本仍为 `1.3.0+10`。包名为 `moe.yutro.yomiru.release`，与正式包 `moe.yutro.yomiru` 数据隔离，不覆盖它；可能覆盖以前安装过的同名并排测试包。
- 两个包的名字可能都显示为 Yomiru，可在 Android「应用信息」确认包名。测试包需要单独登录，书架、图片和正文缓存也不与正式包共享。
- 对比速度时，用同一设备、同一网络、相同作品、相同字号/排版/省流设置。不要拿 Debug 的卡顿程度与 Release 比较。
- 冷缓存与热缓存分开比较。测试包第一次没缓存，比已经长期使用的正式包慢，不一定是退步；分别正常打开同一本书一次后再比较。
- 每种操作重复 3 次，记录中间的一次耗时。手机降温后再测，尽量避免一边充电一边压测。除阅读任务测试外，每轮可先强行停止两个包，再只启动其中一个。
- 不需要清除系统应用数据或卸载正式版。应用内「清除缓存」也仅清理可重新加载的内容；重要阅读进度建议测试前截屏留存。

## 1. 阅读时长与任务中心

1. 用自己的账号进入未锁定章节，正常阅读约 80 秒，然后退出阅读器进入任务中心。
2. 记下「今日阅读」进度；不再进入阅读器，下拉刷新 3 次，并退出、重进任务中心一次。
3. 回到同一章再读约 80 秒，再查看任务中心。
4. 单独测试锁屏/切后台约 2 分钟，回到任务中心检查；另一轮可短暂断网后恢复网络再刷新。

应当：首次显示服务器确认的真实阅读进度，单纯刷新任务中心不再把同一段阅读时间反复加上；同一章第二次阅读仍会计时，后台时间不应计入。显示按分钟取整、服务端响应延迟都是可能的，不能要求每秒精确对应。

负优化信号：正常前台阅读多分钟仍一直为 0；每刷新一次就增加；同章重新进入后不再累计；退出阅读器长时间卡住。网络异常时应记下是否仅断网复现，以及恢复后能否同步。

这些修复不会直接发放奖励，是否完成、是否能领取仍以服务器判断为准。请求超时可能存在“服务端已接收但客户端未收到确认”的不确定性；客户端去重不能替代服务端幂等校验。

## 2. 每日任务跨天与账号隔离

1. 当天正常完成并领取一个任务，刷新确认其已领取。
2. 保留应用到第二天，不先杀进程，返回任务中心下拉刷新。
3. 如有第二个自己的账号，再测试退出本机账号后登录另一个账号。

应当：新一天显示服务器当天的实际状态，不会被昨天的本地「已领取」覆盖；另一账号也不会沿用前一账号的领取状态。

负优化信号：服务器当天任务明明未完成，应用仍一直显示已领取；或者当日刷新后已领取又错误变为可领。不要通过修改手机时间来模拟真实领取，服务器的日期不会跟着设备改变；跨天分支已经有可控时钟的自动化测试。

## 3. 封面模糊不串书

1. 设置封面模糊为「全部」，关闭省流，打开首页或书架。
2. 点眼睛揭开一本书，然后刷新、切换排序或删除本机书架中另一条测试记录，让这个位置换成其它作品。
3. 单列和网格各测一次，再尝试其它书的眼睛按钮。

应当：其它作品仍然模糊；揭开操作只影响当前这本书。没有权限标记的普通书是否模糊，取决于你选择的是「全部」还是「勇者」。

负优化信号：换了书但封面继续裸露；眼睛不能揭开；一次普通重绘就立刻把同一本书重新盖住。

## 4. 隐藏作品之后仍能分页

1. 开启「隐藏勇者书籍」，浏览首页、搜索结果、分区频道，以及用户主页的作品/书架/动态。
2. 持续下滑。若遇到当前一整页都被隐藏的情况，观察是否自动寻找后续内容。
3. 连续过滤多页时点击「继续加载」。加载中断网，观察错误提示；恢复网络后点重试。
4. 关闭隐藏设置，检查原列表是否仍可正常显示。搜索页可快速更换关键词，确认最后只展示最新一次搜索的结果。

应当：隐藏当前页不再等于“加载完了”。空列表最多自动补两页，之后让你手动继续，避免一口气请求大量隐藏内容。正常列表仍能触底加载；失败时停止自动重试。

负优化信号：没有继续加载入口；重复同一页；列表跳回旧关键词；一直请求、一直转圈而无法重试。若正式站当前没有整页都被过滤的数据，不必特意制造，该分支已有模拟接口的页面测试。

## 5. 用户主页响应与后台查询

1. 找一个发布作品和公开书架都较多的用户，打开主页并切换这两个标签，连续滑动两三屏。
2. 返回上一页，马上打开另一个用户，重复数次。
3. 再次进入第一个用户，比较首次和重复进入的感受。

应当：公开资料先显示，缺失的勇者标记按实际构建到的书卡补充；相关后台查询最多并发 2 个，重复查询会合并，退出页面后未开始的任务跳过。

负优化信号：资料卡更慢出现；返回后明显持续发热/占网；有标记的书长期显示错误；过滤后普通作品也消失。

边界：这里只抽样检查目录来补充展示信息，没有把抽样结果当作完整访问权限。未发现勇者章节的结果只短暂复用 5 分钟，不能保证整本书所有章节都公开；正式阅读权限仍由服务器决定。新出现的标记比原来略晚，不等于整个主页加载变慢。

## 6. 插画、阅读进度和内存

1. 打开多插画的长章节，分别以滚动、翻页模式连续阅读；跳到章节中后段，再前后翻几页。
2. 在插画前后各记住一句正文，切换阅读模式，检查文字位置和百分比；放大插画检查完整性和清晰度。
3. 来回切换几个多插画章节，返回首页，再重新进入；连续使用 5～10 分钟观察是否越来越卡、发热或闪退。
4. 已加载的章节测试断网重开。开启省流后检查尚未加载的插画仍由你点击加载。
5. 有后台预取时返回设置，点「清除缓存」，完成后退出重开再检查占用和插画重新加载。

应当：内存只预热阅读位置附近最多 2 张插画，使用与显示层相同的解码宽度；其它图片只做受限的磁盘预取，所有这些后台下载共用最多 3 个并发位。退出页面、开启省流或清理缓存后，未开始的预取不应继续执行。

负优化信号：已缓存插画也长时间空白；出现裁切/变形/显著模糊；切换模式后正文位置或进度大幅跳动；连读后内存不断上涨并闪退。

取舍：降低预解码数量后，第一次跳到很远、尚未加载的插画可能短暂等待；这需要和整体滑动流畅度及内存表现一起判断。清理缓存可能需要先等正在执行的后台下载收尾，不能承诺断网时也瞬间清完。

## 7. 设置与 Release 冒烟测试

- 深色/浅色分别打开设置，测试清除缓存、关于、仓库链接、更新检查，以及退出登录弹窗后取消。
- 使用自己的账号测试一次登录、打开受限章节的正常权限提示、简繁切换、分享面板和图片保存。
- 任务中心刷新、首页与书架、动态评论和关注操作分别走一遍。设置页拆文件不应改变它们的入口和布局。
- 本地环境只能构建 Android。iOS 分享、Keychain、实际内存峰值与系统返回手势仍需后续在 iPhone/iPad 验证，不能用 Android 的结果代替。

## 如何反馈疑似负优化

记录：设备型号/系统、使用的包、冷缓存还是热缓存、网络情况、作品或用户链接、操作顺序、旧包与新包各 3 次耗时。位置/排版问题带一段短录屏，最好在切换前后能看见同一句正文。

同条件反复慢约 20% 或多次出现新的卡顿，是值得排查的信号，不是精确性能结论。任何可重复的闪退、错误账号状态、封面隐私状态串书或阅读定位偏移，都应视为未通过验收。暂时继续使用未覆盖的正式包即可，不必删除数据。
