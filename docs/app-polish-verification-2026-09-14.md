# 本轮优化与实机验证

本轮基于当前本地工作区修改，保留已有改动。没有修改 README、版本号或工作流，也没有提交、推送、安装 APK。回归测试使用模拟请求，未向官网发送评论、私信、关注、奖励或登出操作。

## 已处理

- 勇者考试结束按钮改为「完成」，仍返回上一级。
- 命名统一为「关注与粉丝」「佩戴 / 取下」「取消点赞」「发布动态」「云端书架」；流量节省说明改为「图片按需加载」。底部导航仍叫「书架」。
- 评论、私信发送期间防重复提交，保留等待期间输入的下一条草稿；发送失败可重试。图片选择和上传使用同一忙碌状态。
- 关注和轻币记录分页失败后停止自动重试；评论追加失败时也不因滚动反复请求。首次、空列表和失败状态按可用区域布局。
- 关注/取消关注同步两类名单、数量及导航栈内的资料卡；旧刷新响应不覆盖后完成的关注操作。手动刷新可以接收其它设备改变的关系。
- 私有页面跟随会话变化重建；消息、私信、关注、轻币记录和勋章页面拒绝旧会话的迟到响应。任务页同时清理旧数据与倒计时。
- 「退出所有设备」必须收到服务端成功响应才提示完成；失败可重试或改选「仅退出本机」。迟到的旧登出响应不清空新账号。
- 横屏设置面板允许滚动；表情区按剩余高度调整；商城大字体说明可换行，勋章中心空状态和按钮高度调整。
- 勋章商城懒构建条目，保留当前页签、滚动位置和刷新期间的旧内容，兑换接口和二次确认不变。
- 睡觉倒计时按截止时间计算，只更新睡觉卡片；恢复前台时校准，领取条件仍由服务器判断。任务骨架屏不再在内容加载完后持续运行。
- 阅读器仅复用最近两套排版结果，内容变化清空，不缓存或改写阅读位置；保留统一正文锚点和插画独占页规则。
- 头像/勋章跨页面共用最多三个预加载任务，跳过已失效页面，重复资源排队去重，显示和预加载共用限尺寸解码。书架状态补查也共享并发上限，复用已核对结果并合并落盘。
- 清理缓存会等待旧头像/勋章预加载结束并跳过未开始任务；各类缓存分别清理，部分失败明确提示失败类别并重新计算占用，不删除账号、本机书架或阅读位置。
- 后续按用户要求移除「每日开宝箱」入口、页面及专用接口，其他任务保留。

## 实机怎么验

建议 Android 和 iPhone 各测一次；横屏需先开启「横屏适配」。只用测试账号验证发布/关注行为，不反复向真实用户发送内容。

| 场景 | 操作 | 正常表现 / 需要反馈的异常 |
| --- | --- | --- |
| 考试文案 | 打开已结束的勇者考试 | 按钮显示「完成」；进入前的一天一次提醒保留 |
| 横屏、大字体 | 横屏打开主题、封面模糊；系统字体调大，再打开两类勋章页 | 选项可滚动到最后；没有裁切、黄黑溢出条，按钮能点 |
| 表情与键盘 | 横屏评论，表情→键盘→表情，再旋转 | 输入栏和表情可见；若跳位，反馈系统/输入法、方向及截图 |
| 防重复发送 | 弱网时连续点击一次提交按钮两下；等待时输入下一条草稿 | 只发送一条；新草稿保留；失败时旧草稿仍在，可手动重试 |
| 分页失败 | 关注/粉丝或轻币记录先载入第一页，断网滑到底 | 只出现一次失败；不持续转圈或刷请求；恢复网络后点击重试 |
| 关系同步 | 粉丝页关注/取消关注，再切关注页、回「我的」或发布者卡片 | 名单、按钮与数量同步；手动刷新仍可查询服务端新状态 |
| 账号隔离 | 测试账号 A 打开私有页面后会话失效，再登录账号 B | A 的名单、消息、轻币和勋章信息不残留；旧请求不能覆盖 B |
| 全设备登出失败 | 使用模拟/受控错误环境验证，不注销正常账号其它设备 | 明确提示未完成全部退出；仅本机退出不调用远程登出接口 |
| 商城刷新 | 兑换页往下滚，弱网下刷新，再等待完成 | 页签不跳回任务勋章，原列表不消失，位置不回顶 |
| 后台倒计时 | 有进行中睡觉任务时切后台几分钟，再返回 | 时间按实际经过时长减少；到时重新核对，不擅自显示领取成功 |
| 阅读器 | 同一长章节滚动/翻页切换、旋转两次、字号改大后改回；另测含插画章节 | 熟悉排版可复用；阅读位置不漂移、无截字，插画仍完整独占一页 |
| 缓存 | 浏览后清缓存，核对占用，再打开书架及阅读器 | 书架和进度不丢；首次重新加载正常；清理失败显示类别而非假报成功 |
| 图片 | 多次进出用户页、商城和关注列表；开启/关闭流量节省 | 小图不明显模糊/变形；离开后预加载不持续堆积；大图查看不受小图解码尺寸影响 |

清理后，仍在展示的页面可能按需重新生成缓存，因此占用不要求长期保持零。网络失败不应把已有页面内容直接清空。

## 性能边界

已验证的是并发/缓存/排版复用规则和布局回归，不是某款手机的帧率或耗电结论。长章节第一次布局、新字号第一次排版仍需主线程字体测量，没有替换渲染引擎。实测请优先比较相同章节、字体、方向、网络环境；记录卡顿是否减少，同时检查进度和图片完整性，不能仅凭首次打开速度判断。
