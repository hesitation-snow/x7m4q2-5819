# 插画切章重载：临时签名缓存修复

## 已确认的原因

用户复现位置：[书籍 1338、章节 317815](https://www.lightnovel.fun/reader/1338/317815)，滚动阅读模式。

连续两次只读获取该页，均返回 8 张插画，同一张图片的文件路径相同，但完整 URL 不同，变化的是 `m`、`t` 参数。应用使用的章节详情接口也返回这种带参数地址。手机上 APK 的 SHA-256 与前一测试包一致，排除了未安装上一版的问题。

首轮只验证了相同完整 URL 下的缓存命中，没有覆盖服务端每次刷新临时签名。这会同时改变磁盘缓存键和 Flutter 图片内存缓存键，所以仅修复 HTTP 过期重验证不足以解决此例。

## 本次修复

- 本地缓存标识与下载地址分离。只对 `https://api.lightnovel.fun/upload-files/images/日期/十六进制文件名.图片扩展名` 这一已确认地址格式，去掉成对且格式有效的 `m`、`t` 作为缓存键；实际网络请求仍使用完整签名 URL。
- 保留所有其它查询参数，未知域名、路径、协议、端口及不完整签名不做合并，避免把不同尺寸、版本或资源误当成同一张图。
- 滚动/翻页阅读器、预热图片、大图查看、相册保存和后台下载统一使用稳定标识；没有改变图片排版和进度算法。
- 一次性索引原缓存的元数据，复用旧签名地址下已下载的文件，不复制图片、不批量下载。清除缓存同步使这个旧索引失效。
- 保留前一轮的按需预取、下载去重、并发上限与明确的清理规则。没有增加服务器请求、遥测或后台上报。
