# Issue #3：勇者书籍识别与筛选修复

> 本文记录前一版“统一识别＋有限抽查”的交付。混合权限书后部漏识别的后续实现，已改为分轮完整目录核验；当前行为与预算请以[混合目录核验说明](mixed-catalog-verification.md)为准。

原报告：https://github.com/hesitation-snow/Yomiru/issues/3

## 修复范围

这次仅修复识别、已识别结果传播与已有列表的筛选响应。**“隐藏勇者书籍”与“封面模糊”仍然是独立设置**，识别修复不会更改用户的封面设置，也不会给用户增加正文访问权限。

### 统一、限定作用域的识别规则

- [权限分类器](../lib/api/book_access.dart)对书籍/章节使用统一规则，区分`unknown`、`public`、`brave`。
- 合并`is_brave/isBrave`、`brave_required/braveRequired`等正标记，不再让旧别名的0遮住另一别名的1。
- 规范化`access_type`的首尾空格及大小写，书籍、章节列表与正文均读取已支持的`meta_json.brave_scope`路径；额外容忍JSON编码的元数据，但这项属于兼容性处理，并非声称已捕获线上这种响应。
- `locked`、金币价格、普通403、用户/发布者的勇者身份，不当作这本书的勇者证据；不递归遍历用户资料寻找标记。
- 无权限字段、false标记、空卷与有限公开章节样本，均不证明整本书公开。
- 没有新增硬编码书籍ID；新增算法测试使用任意新ID及空已知集合，不依赖原有的legacy预置ID。

### 已确认结果对已有对象立即生效

- [模型](../lib/api/models.dart)的`isBrave/accessStatus`可读取后来确认的正标记，不要求列表重新拉取/重新解析。
- [缓存与事件](../lib/api/store.dart)采用positive-only集合、批量串行保存与`braveBookRevision`通知。
- [API边界](../lib/api/lk_api.dart)汇入列表、详情、历史、公开书架/发布列表、阅读入口、章节列表与正文的正标记。
- 首页、分区/排行、搜索、书架、历史及个人主页收到事件后重新计算已有筛选；分区横向最新预览也遵守隐藏开关，预览缓存保留权限状态。

### 有界补查，不遍历全书

[补查服务](../lib/services/book_access_probe.dart)的限制：

| 项目 | 限制 |
|---|---|
| 并发 | 2 |
| 在途及排队书籍总数 | 最多32 |
| 单次时间预算 | 8秒 |
| 每书请求 | 最多4个：详情、一个卷页、最多两个卷的各一个章节页 |
| 抽样范围 | 卷页最多3卷，选首个及最后一个返回卷；每个章节页最多5章 |
| 未明确结果 | 保持unknown，5分钟冷却，不持久化为public |
| 正标记优先级 | 新确认的正标记可立即覆盖先前冷却 |

- 仅在隐藏开关开启、省流关闭且对应页面仍有效时补查；离页后排队任务跳过，在途查询不继续采样下一接口。
- 网格和单列的公共卡片以及页面内联封面都携带书籍身份。
- 移除了个人主页的旧重复补查入口，避免其绕开统一的生命周期保护。
- **有限补查只提高正标记召回率；若接口完全不提供证据，仍保持未知可见，不宣称全书已查完。**
