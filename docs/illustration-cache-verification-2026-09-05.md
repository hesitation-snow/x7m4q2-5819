> 本文件记录首轮修复及其旧测试包。随后已确认站点插画的临时签名变化会使完整 URL 缓存失效；最新策略和测试见 `illustration-signature-cache-verification-2026-09-05.md`。

这是 `device-regression-checklist-2026-09-05.md` 之后的插画缓存补充修复。保留前一份 APK，便于对比。本次不改正文排版、阅读进度换算、头像/勋章/动态图片的更新策略，也不修改 README 或推送仓库。

## 改动与边界

- 小说插画继续使用原来的磁盘缓存目录。完整 URL 对应的文件仍在时直接复用，不因 HTTP 过期标记再次请求服务器；内存图片被回收、重新打开阅读器后也适用。
- 当前阅读位置附近最多预取两张插画，不再批量下载整章或前后章的插画。前后章的正文预取保留；屏幕实际显示但未缓存的图片仍会按需加载。
- 阅读器显示、后台预取、大图查看、保存相册共用同一套下载去重与最多三个并发下载的限制。缓存命中不需要排队等待网络。
- 离开页面会跳过尚未开始的无效预取；已经发出的下载可以完成并留存缓存。清除缓存会等待在途写入结束，避免清完又被旧请求写回来。
- URL 的查询参数仍参与缓存识别，不删除签名参数。新地址会下载新文件；服务器在同一地址替换插画时，需要在设置里清除缓存后重新加载。
- 缓存不是永久归档：保留原来的 30 天未使用清理策略、最多 2000 个文件，系统也可能回收缓存。应用重启本身不会主动清空插画。
- 磁盘读取和图片解码仍需时间，极短暂的占位/渐显不代表重新下载。判断网络改善应看对应插画 URL 的请求及字节量，不是整个应用的连接总数；章节、目录、账号与阅读进度请求仍可能正常发生。

## 手机上怎么验证

1. 关闭省流模式，在测试版打开一章含多张插画的小说，停在一张插画处，等待显示完整。
2. 返回书籍详情，重新进入同章、同一位置，重复三次。应直接复用已下载插画，不再重复传输同一张图。
3. 强行停止测试应用后重新打开同章，再测试一次。若正文可离线打开，也可以断网后进入，确认已经看过的插画仍可显示。不要把从未加载过的远处插画当作离线缓存验证目标。
4. 点开同一张插画的大图并保存到相册。应完整显示并保存；已有文件不应重复下载。相册权限和系统保存失败仍会正常提示。
5. 跳到本章尚未看过的插画附近，或者首次进入新章。此时出现少量下载正常；不应因为打开一章就把前后章的整批插画下载下来。
6. 开启省流模式：已有插画可直接显示，未缓存插画仍需手动点击加载。最后可按需测试「清除缓存」，清除后首次重新看插画发生下载是预期行为。
